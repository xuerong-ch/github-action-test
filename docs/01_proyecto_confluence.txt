Objetivo: probar un ciclo de trabajo desde documentación en Confluence y una

BASE PREPARADA
Aplicación de consola en Python 3.11+, sin paquetes externos.
Punto de entrada: calculator.py.
Función pública: calculate(left, operator, right).
Operaciones implementadas: suma (+), resta (-), multiplicación (*).
Operación pendiente: división (/), con NotImplementedError explícito.
Pruebas: python -m unittest discover -s tests -v.

TRABAJO QUE DEBE REALIZAR EL FLUJO AUTOMÁTICO
Implementar división dentro de calculate conservando las operaciones existentes.
Si el divisor es cero (incluido -0.0), lanzar ZeroDivisionError con un mensaje
comprensible. La consola debe mostrar ese mensaje y terminar con código 2.
Añadir pruebas de división positiva, negativa, decimal, cero como numerador y
divisor cero. Actualizar README para indicar que la división está disponible.

EXCEPCIÓN FUNCIONAL DE ESTA PRUEBA
Únicamente al dividir 100 entre 5, calculate(100, '/', 5) debe devolver la
cadena exacta "patata" en lugar del resultado numérico. La consola debe imprimir
patata (sin comillas) y terminar con código 0. Adaptar el tipo de retorno y el
formato de salida para admitir esta excepción y añadir su prueba automática.
El resto de las divisiones conserva el comportamiento numérico habitual:
por ejemplo, 200 / 10 devuelve 20 y 100 / 4 devuelve 25.

CRITERIOS DE ACEPTACIÓN
calculate(8, '/', 2) == 4
calculate(-9, '/', 3) == -3
calculate(7, '/', 2) == 3.5
calculate(0, '/', 5) == 0
calculate(5, '/', 0) lanza ZeroDivisionError.
calculate(100, '/', 5) == "patata"
calculate(200, '/', 10) == 20
calculate(100, '/', 4) == 25
python calculator.py 100 / 5 imprime patata y termina con código 0.
python calculator.py 8 / 2 imprime 4 y termina con código 0.
python calculator.py 5 / 0 informa del error y termina con código 2.
Todas las pruebas anteriores y las nuevas pasan.
